# 声文对齐采用拼音匹配而非字符串匹配

声文对齐需要将 ASR 输出的文字与文稿进行模糊匹配，以确定当前朗读位置。中文 ASR 经常输出同音别字（如"的/得/地"、"在/再"、"做/作"），直接字符串匹配在这种场景下召回率极低。因此采用拼音序列匹配：将文稿预处理为拼音序列（带声调），ASR 输出的文字也转为拼音，然后计算拼音相似度（精确拼音匹配 1.0，声母匹配 0.2），结合滑动窗口和距离惩罚确定最佳匹配位置。

## 考虑过的选项

- **编辑距离（Levenshtein）**：对同音别字太敏感，一段 10 字的话如果 ASR 错了 2 个同音字，相似度已经降到 60% 以下，实际中频繁丢失位置。
- **连续字符精确匹配**：最长公共子串之类的方式，但对 ASR 错误几乎零容忍，仅适合 ASR 准确率极高的场景。
- **拼音匹配（选中）**：对同音错误天然鲁棒，计算量可接受（纯 Java 在手机上毫秒级）。代价是拼音相同但意义不同的字（如"长"读 zhǎng 或 cháng）可能产生误匹配，但通过滑动窗口和距离惩罚可以有效抑制。
